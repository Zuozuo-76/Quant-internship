## 三、数据降采样与复权

### 3.1 交易分钟网格：`trading_minutes()`

```python
minutes = list(range(915, 926))
for hour, start, end in (
    (9, 30, 59), (10, 0, 59), (11, 0, 30),
    (13, 0, 59), (14, 0, 59), (15, 0, 0),
):
    minutes.extend(hour * 100 + minute for minute in range(start, end + 1))
```

这段代码按题目把交易日展开为 253 个分钟点：09:15-09:25 集合竞价、09:30-11:30 上午连续竞价、13:00-15:00 下午时段。午休时间不在索引中，15:00 作为收盘分钟被显式保留。单元测试同时检查了网格长度、时段边界和无重复。

### 3.2 复权因子：`load_adjustment()`

`adjfactor.pkl` 被读成“日期 x 股票”面板，日期统一为 `YYYYMMDD`，股票代码去掉交易所后缀。如果去后缀后出现重复代码，程序直接报错。因子表按日期排序，再向前、向后填充缺失值。在正式导入前，`import_data()` 还会一次性检查所有交易日和股票是否都被复权表覆盖。

价格与金额使用两种口径：

```python
raw_price = df["Price"].astype(float) / 100.0
adjusted_price = raw_price * adjustment
amount = raw_price * df["Volume"]
```

- OHLC 使用 `Price / 100 * adjfactor`，用来缓解分红配股等事件导致的价格不连续。
- 成交额使用实际成交价 `Price / 100 * Volume`，不随复权价改变。

### 3.3 单只股票汇总：`summarize_stock()`

函数首先用明确数据类型读取 `Time, Price, Volume, BSFlag`，并严格检查列集合和 `BSFlag` 取值。稳定排序保证同一时间下的原始先后顺序不被改变。

| 输出字段 | 日频定义 | 分钟频定义 |
|---|---|---|
| `open` | 当日第一笔复权价 | 当分钟第一笔复权价 |
| `high` / `low` | 当日复权价最大/最小值 | 当分钟复权价最大/最小值 |
| `close` | 当日最后一笔复权价 | 当分钟最后一笔复权价 |
| `volume` | 全日成交量之和 | 分钟成交量之和 |
| `trade_count` | 全日逐笔记录数 | 分钟逐笔记录数 |
| `amount` | 实际价 x 成交量的全日合计 | 实际价 x 成交量的分钟合计 |
| `buy_volume/amount` | 只累加 `BSFlag=0` | 只累加 `BSFlag=0` |
| `sell_volume/amount` | 只累加 `BSFlag=1` | 只累加 `BSFlag=1` |

`BSFlag=2` 的集合竞价成交会进入总成交量和总成交额，但不进入主买/主卖子项。因此 `buy_volume + sell_volume <= volume` 是正常关系，不要强行令两者相等。

### 3.4 空值填充：不让未来价格倒灌

```python
close_filled = (
    minute_by_field["close"].ffill()
    .fillna(previous_close)
    .bfill()
)
for field in PRICE_FIELDS:
    minute_by_field[field] = minute_by_field[field].fillna(close_filled)
for field in ZERO_FIELDS:
    minute_by_field[field] = minute_by_field[field].fillna(0)
```

日频无成交价格用前一日复权收盘价填充，量、笔数和金额填 0。分钟频先在当日向前填充，开盘前置空白再用昨日收盘填充；只有数据集第一天没有昨日价时才使用当日首个可观察价向后补齐。这个顺序避免常见错误：如果一开始就对全日 `bfill()`，会把当日稍后才出现的价格引入更早分钟。

### 3.5 全量导入：`import_data()`

`import_data()` 按日期循环，每天先建立“股票 x 11 字段”日频空表和 11 张“253 分钟 x 股票”空表，再逐股调用 `summarize_stock()` 回填。当日完成后立即写出 11 张分钟 CSV，所有日期完成后再把日频行堆叠成 11 张宽表。

已验证输出：

- 日频每字段为 302 x 300，共 11 张表。

- 全量审计检查了 1,759,661 个无成交单元格的填充口径。

## 四、因子构建

### 4.1 输入和输出

`construct_factors.py` 只读取日频 `close, high, low, amount, volume, buy_volume, sell_volume`。`load_wide()` 统一日期类型、排序并保留 6 位代码；`save_wide()` 把索引写回 `YYYYMMDD`。`build_factors()` 生成四张宽表，再通过 `stack()` 合并成 `factor_long.csv`，同时写出因子中文名、公式和类型元数据。

| 因子 | 公式和直觉 | 方向解读 |
|---|---|---|
| `amount_mean_sd_log` | `log(1 + sd(MA1, MA5, MA10, MA20))`；衡量成交额不同窗口均值的离散程度 | 数值越大，短中期成交额状态越不一致 |
| `buy_sell_imbalance_surprise_10d` | 当日主动买卖不平衡减去此前 10 日均值；其中 `OI=(buy_volume-sell_volume)/(buy_volume+sell_volume)` | 正值表示当日主动买盘相对历史常态异常增强；负 Rank IC 表示次日更偏向短期反转 |
| `intraday_range_10d` | 10 日平均 `(high - low) / close` | 数值越大，日内波动越强 |
| `reversal_5d` | `-(close / close.shift(5) - 1)` | 近 5 日跌得越多，反转因子越高 |

题目示例因子的关键实现如下：

```python
amount_means = [
    amount.rolling(window, min_periods=window).mean()
    for window in (1, 5, 10, 20)
]
stacked = np.stack([table.to_numpy() for table in amount_means], axis=0)
valid = np.isfinite(stacked).all(axis=0)
factor[valid] = np.log1p(np.std(stacked[:, valid], axis=0, ddof=1))
```

`min_periods=window` 保证每个移动均值只在窗口完整后才有值。四个时窗必须全部有限才计算标准差，`ddof=1` 使用样本标准差，`log1p()` 压缩偏态并避免对 0 直接取对数。

## 五、因子清洗、IC 和五分组评价

### 5.1 目标收益与面板清洗

因子评价的目标是下一交易日收盘到收盘收益：

```python
next_return = close.shift(-1) / close - 1
panel = clean_factor_panel(factors, next_return)
```

`clean_factor_panel()` 把每个因子的宽表和收益宽表展开为 `date-code` 长表，然后按日做横截面处理：

1. 仅保留因子和未来收益都是有限数的样本，每日至少 20 只股票。
2. 用当日因子的 1% 和 99% 分位数做缩尾，减少极端值影响。
3. 用当日均值和样本标准差做 z-score，使不同因子可以参与后续线性合成。

### 5.2 IC、Rank IC、IR 和 ICIR

每个交易日、每个因子都计算两种横截面相关：Pearson 相关是 IC，Spearman 秩相关是 Rank IC。时序均值除以时序标准差得到 IR，再乘 `sqrt(252)` 得到年化 ICIR。

```python
ic = np.corrcoef(x, y)[0, 1]
rank_ic = spearmanr(x, y).statistic
ir = ic_series.mean() / ic_series.std(ddof=1)
icir = ir * math.sqrt(252)
```

IC 的负号不等于因子无效，而是说因子值越大，下期收益倾向越低。如果这种负相关稳定，在组合中乘以负的历史 IC 后反而能正确翻转方向。

### 5.3 五分组和 Q5-Q1

对每日横截面的标准化因子做百分位排名，再用 `ceil(rank * 5)` 分到 Q1-Q5。每组等权收益通过连乘得到净值，`Q5 - Q1` 作为当日多空收益。这一步既看相关系数，也检查因子收益是否具有分层和单调性。

## 六、IC 加权 Top 10 组合回测

### 6.1 两种持有期收益

```python
if mode == "close_to_close":
    result = close.shift(-1) / close - 1
elif mode == "next_open_to_open":
    result = open_price.shift(-2) / open_price.shift(-1) - 1
```

- `close_to_close`：信号日 t 的收盘到 t+1 收盘。程序将交易日记为 t，等价于假设能用 t 日收盘数据并在同一收盘价成交，所以仍偏乐观。
- `next_open_to_open`：信号日 t 之后，在 t+1 开盘买入，到 t+2 开盘计算持有收益，交易日记为 t+1。

### 6.2 两种因子权重：错误对照与修正方案

```python
if strategy == "leaky_same_day_ic":
    weights["weight"] = weights["raw_ic"]
elif strategy == "historical_20d_ic":
    weights["weight"] = weights.groupby("factor")["raw_ic"].transform(
        lambda s: s.shift(1).rolling(20, min_periods=20).mean()
    )
```

`leaky_same_day_ic` 用当日因子与未来持有期收益计算当日 IC，再立即当作权重。因为调仓时并不知道未来收益，这是典型的前视偏差。该结果只能用来说明数据泄漏会把业绩夸大到何种程度。

`historical_20d_ic` 先对单因子 IC 整体滞后一天，再使用过去 20 日均值。所以任意信号日的权重都只由当时已知的历史数据决定，这才是可用于策略结论的版本。

### 6.3 信号、选股、换手和费用

每只股票的综合信号为“标准化因子 x 历史 IC 权重”在四个因子上求和。每日按信号从高到低选 10 只，目标权重各 10%。卖出换手由“当前漂移权重超出新目标权重的部分”累加得到，费用为期初净值 x 卖出换手 x 0.0005。买入费用按题目设定为 0。

```python
signal = sum(factor_z * weight)
target = top_10_by_signal
fee = nav * sell_turnover * 0.0005
nav_end = (nav - fee) * (1 + target_return.mean())
```

## 七、PyTorch LSTM 分钟涨跌预测

### 7.1 样本和特征：`make_dataset()`

模型默认选取分钟表第一只股票，当前实验为 `000012`，使用前 60 个交易日。每一天单独生成长度 20 的滑动窗口，不让序列跨夜连接。标签是窗口后一分钟收盘价是否严格大于当前收盘价。

| 特征 | 计算 | 信息含义 |
|---|---|---|
| `log_return` | `diff(log(close))` | 最近一分钟收盘收益 |
| `range` | `(high - low) / close` | 分钟内波动幅度 |
| `log_volume` | `log1p(volume)` | 压缩后的成交活跃度 |
| `buy_sell_imbalance` | `(buy - sell) / max(volume, 1)` | 主动买卖方向 |
| `time_position` | 从 0 到 1 的日内位置 | 开盘/收盘时段效应 |

### 7.2 模型结构：`TorchLSTM`

```python
self.lstm = nn.LSTM(
    input_size=5, hidden_size=16, batch_first=True
)
self.classifier = nn.Linear(16, 1)

sequence, _state = self.lstm(x)
logit = self.classifier(sequence[:, -1]).squeeze(-1)
```

输入形状为 `batch x 20 x 5`。单层 LSTM 输出整段隐状态，代码只取最后一个时刻，再用线性层输出一个 logit。训练时用 `BCEWithLogitsLoss`，预测时再通过 sigmoid 转为上涨概率。

### 7.3 时间切分、标准化和训练：`train()`

样本按原时间顺序切成 70% 训练、15% 验证和 15% 测试，没有随机打乱切分。特征均值和标准差只由训练集估计，然后应用到验证和测试集，避免预处理阶段泄漏未来信息。

优化器为 Adam，学习率 0.003，batch size 128，训练 8 轮。每个 batch 执行清梯度、前向传播、反向传播、梯度范数裁剪到 5.0、参数更新。每轮都计算训练集和验证集指标，保留验证损失最小的检查点。

| 训练 | 9,786 | 36.87% | 63.13% | 63.72% | 52.07% | 0.6028 |
| 验证 | 2,097 | 40.01% | 59.99% | 60.52% | 51.95% | 0.5772 |
| 测试 | 2,097 | 40.44% | 59.56% | 58.99% | 51.05% | 0.5654 |

测试集准确率 58.99% 低于“永远预测不涨”的 59.56% 多数类基线；平衡准确率 51.05% 只略高于随机水平，AUC 0.5654 说明有弱排序信号，但远不足以声称可交易。这一拓展的主要价值是完成了从分钟表、特征、序列、训练、检查点到测试输出的端到端流程。

### 7.4 输出文件

- `model.pt`：模型权重、特征列表、标准化参数、股票代码、序列长度和最优轮次。
- `model_metadata.json`：不含大型张量的可读元数据。
- `training_history.csv`：每轮训练/验证损失和指标。
- `metrics.csv`：训练、验证、测试三个分割的统一评价。
- `test_predictions.csv`：测试集每个时点的真实标签、上涨概率和 0/1 预测。

## 九、复现方式和 README 中需注意的一处缺口

项目应使用工程虚拟环境 `.venv/bin/python`，避免系统 Python 缺包或版本不一致。从原始数据完整复现的精简顺序为：

```bash
.venv/bin/python pipeline_code/downsample_tick_data_and_apply_adjustment.py \
  --input data --adjfactor adjfactor.pkl --output processed
.venv/bin/python scripts/build_kline_csv.py
.venv/bin/python scripts/analyze_factors_backtest.py
.venv/bin/python scripts/train_lstm_pytorch.py \
  --max-dates 60 --epochs 8 --device auto
.venv/bin/python scripts/build_report.py
.venv/bin/python scripts/validate_outputs.py
.venv/bin/python -m unittest discover -s tests -v
```

当前 README 的命令列表分别调用了 `construct_factors.py` 和 `evaluate_factors.py`，但没有显式调用回测生成步骤；而 `build_report.py` 又需要已存在的 `backtest/backtest_summary.csv`。因此，对于一个干净目录，需要补上 `scripts/analyze_factors_backtest.py`。该脚本会再次构建因子和评价结果，因此上面的精简路线不再单独执行两个拆分脚本。如果为了教学需要展示拆分步骤，可先运行构建与评价脚本，再运行合并脚本，但会重复前两步。

## 十、结论、边界与后续改进

这份作业的主任务和两个拓展都已经完成，而且产物结构、维度、填充逻辑和模型文件均通过自动化检查。因子端有明确结果：成交额多窗口因子呈稳定负相关，5 日反转因子呈正相关。组合端的可信版本在两种交易口径下都取得正收益，但次日开盘口径明显弱于收盘口径，说明结果对成交假设敏感。LSTM 完成了流程验证，但测试准确率低于多数类基线，不应包装成强预测能力。

当前结果还有四个主要边界：

1. 收盘信号按同一收盘价成交偏乐观，应进一步滞后信号或模拟收盘集合竞价。
2. 回测只计题目指定的卖出手续费，未计买入成本、滑点和冲击成本。
3. 数据不含行业、市值、停牌和涨跌停状态，因子未做行业/规模中性化和可交易过滤。
4. LSTM 只使用单只股票和前 60 日，下一步应扩展到多股票 walk-forward，并把概率阈值、换手、延迟和成本统一放入样本外评价。
